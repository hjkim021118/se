## 1. 개요 (Introduction)

### 1.1 문서의 목적
본 문서는 ‘클라우드 파일 공유 시스템(미니 드라이브)’ 프로젝트의 개발 최종 단계에서 수행된 단위, 통합, 시스템 테스트의 설계 사양과 수행 결과를 종합적으로 기록하여 제품의 최종 품질을 검증하고 배포 가능 여부를 판단하는 것을 목적으로 함

### 1.2 테스트 범위 및 대상
* **대상 시스템**: 웹 기반 클라우드 파일 공유 시스템 (Mini Drive)
* **검증 범위**:
    * 계정 관리, 파일/폴더 관리, 공유 및 협업 기능 등의 기능적 요구사항 (FR-001 ~ FR-005)
    * 가용성, 성능 효율성, 자원 효율성, 보안성, 호환성 및 이식성 등의 비기능적 품질 요구사항 (NFR/QR)

## 2. 테스트 환경 및 일정 (Environment & Schedule)

### 2.1 테스트 환경 구성
* **인프라 환경 (서버)**: AWS EC2 (Ubuntu 22.04 LTS), MySQL 8.0, Node.js / Spring Boot 인프라 기반 배포 환경
* **클라이언트 환경 (검증 PC)**: macOS Sonoma 및 Windows 11 환경 워크스테이션
* **검증 브라우저**: Google Chrome (최신 버전), Apple Safari (최신 버전), Microsoft Edge (최신 버전)

### 2.2 테스트 수행 일정
* **WBS 단계**: 테스트 및 검증 단계 (프로젝트 일정 계획 기준 9~10개월 차 수행 완료)

## 3. 테스트 예외사항 관리 (Exception Management)

### 3.1 테스트 중단 기준 (Suspension Criteria)
다음 조건 중 하나라도 발생할 경우, 진행 중인 테스트를 즉시 중단하고 결함 리포트를 발행함
* **시스템 블로킹 결함**: 빌드 및 배포 실패, DB 커넥션 풀 고갈 등으로 인해 테스트 대상 시스템에 정상적인 접근이 불가능한 경우
* **치명적 보안 결함**: 데이터 암호화(SSL/TLS, AES-256) 파이프라인이 정상 작동하지 않아 테스트 데이터 유출 위험이 있는 경우
* **인프라 다운**: 테스트 부하(200명 동시 접속) 중 AWS EC2 서버가 다운되거나 복구 불가능한 Hang 상태에 빠지는 경우

### 3.2 테스트 재개 조건 (Resumption Criteria)
중단된 테스트를 다시 시작하기 위해서는 다음 조건을 모두 충족해야 함
* **형상 관리 및 패치 완료**: 중단 원인이 된 소스코드 및 인프라 설정 오류가 수정되어 형상 관리 시스템(Git)에 반영되고, 스테이징 서버에 정상 재배포되어야 함
* **회귀 테스트(Regression Test) 통과**: 결함 수정이 기존에 통과했던 다른 기능(로그인, 권한 등)에 부작용(Side Effect)을 주지 않음을 선행 검증해야 함
* **품질 담당자 승인**: 개발 총괄 및 QA 담당자가 결함 조치 상태를 최종 확인하고 테스트 재개를 승인해야 함
