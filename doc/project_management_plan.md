# 클라우드 파일 공유 시스템(미니드라이브) 프로젝트 관리 계획서 (Project Management Plan)

## 1. 개요 (Introduction)

### 1.1 문서의 목적
본 문서는 '클라우드 파일 공유 시스템(미니 드라이브)'개발에 대한 내용을 정리하여 프로젝트 진행에 있어 지표로 삼음을 목적으로 함

### 1.2 프로젝트 개요
- **정의**: 여러 팀이 동시 협업하는 환경에서 문서, 설계 파일 등 프로젝트 자료를 중앙 집중식으로 관리하는 시스템
- **배경**: 이메일/메신저 공유로 인한 버전 관리의 어려움, 파일 검색 시간 과다 소요, 보안 유출 위험 등의 문제를 해결하고자 함
**주요 기능**
| 번호 | 설명 |
| **중앙 관리** | 조직 내 모든 파일을 중앙 저장소에서 통합 관리 |
| **사용 편의성** | 직관적인 업로드/다운로드 및 폴더 체계를 제공 |
| **협업 지원** | 팀원 간 권한 기반 파일 공유 및 외부 협력업체 링크 공유를 지원 |
| **효율적 검색** | 파일명 및 메타데이터 기반의 빠른 검색 기능을 제공 |

### 1.3 프로젝트 목표
- 조직 내 파일 중앙에서 관리
- 사용자가 파일 쉽게 업로드/다운로드
- 팀원 간 파일 공유 지원
- 파일 검색 기능 제공
- 보안 유지하며 외부 사용자와 파일 공유 지원

### 1.4 용어 정의
- **미니 드라이브**: 본 프로젝트에서 구축하는 클라우드 파일 공유 시스템의 명칭
- **공유 링크**: 외부 사용자가 파일을 다운로드할 수 있도록 생성된 고유 URL

### 1.5 참조 문서
- 소프트웨어 공학 강의 교안: Ch.05 프로젝트 관리
- 요구사항정의 문서 `docs/requirements.md`

## 2. 개발 계획 (Development Plan)

### 2.1 개발 절차 모형
- **SCRUM 모델**: 팀원 간 의사소통 원활하게 하여 사용자의 불명확하고 자주 변경 되는 요구사항 빠르게 반영 가능
- **객체지향 방법론**: 소프트웨어 모듈의 한 단위가 되어 분석, 테스트 유지보수, 확장 등에 용이함

### 2.2 작업 분할도 (WBS)
| 작업 명칭 | 상세 활동 (Task) |
| :--- | :--- |
| **요구분석** | 계획서 검토, 기존 시스템 조사, 요구 분석 및 정의, 필요한 기능 정의 |
| **시스템 설계** | DB 스키마 설계(ERD), 시스템 아키텍처 정의, 상세 설계 |
| **시스템 구현(코딩)** | 요구 기능 구현, 서버 및 DB 구축, 각 부분 기능의 통합 |
| **테스트 및 검증** | 각 단계별(단위, 통합, 시스템 수용)테스트 수행 |
| **배포 및 인도** | 최종 빌드, 사용자 매뉴얼 작성, 프로젝트 보고서 작성 |

- **플랫폼**: 웹 서비스 기반 (React/Vue.js + Node.js/Spring Boot 등)

## 4. 품질 관리 (Quality Control)

### 4.1 팀 미팅 계획
- **데일리 스크럼**: 매일 15분간 전일 진행 상황 및 장애 요인 공유.
- **주간 보고**: 매주 금요일 주간 성과 및 차주 계획 검토.

### 4.2 변경 사항 관리 방법
- 모든 요구사항 변경은 **변경 요청서(CR)**를 통해 공식 접수하며, 팀장 승인 후 베이스라인에 반영합니다.

### 4.3 산출물 관리 방법  
산출물의 체계적인 추적과 가독성을 확보하기 위해 표준화된 명명 규칙을 적용  

**(1) 파일 명명 규칙 (Naming Convention)**
| 카테고리 | 방법 | 예시 |
| :--- | :--- | :--- |
| **소프트웨어** | `버전_산출 일자.확장자` | ex. v1_2019_10_11.exe |
| **문서** | `[팀명]_문서명_YYMMDD_Doc-버전.확장자` | ex. 김검정 프로젝트관리계획서_191025_Doc-001.hwp |
| **기타** | `해당 파일의 목적이 명확하게 드러나는 이름.확장자` | ex. 191025_video.h264 |  

**(2) 저장 및 형상 관리 담당자**
- **소프트웨어**: 파일명 맨 앞에 버전 기재 (담당자: 팀원 전체)
- **문서**: 파일명 맨 뒤에 날짜 기재, 문서 내에 제/개정 이력 수정 (담당자: 팀원 전체)
- **기타**: 파일명 앞에 날짜 기재, 필요한 경우 숫자 추가하여 기재 (담당자: 팀원 전체)
- **저장소**: 모든 소스 코드는 **GitHub**에 업로드하며, 문서는 클라우드 공유 폴더를 활용

### 8. 자원 관리 (Resource Management)

프로젝트 목표 달성을 위해 필요한 인적, 물적 자원을 다음과 같이 할당

### 8.1 인적 자원 및 역할 (R&R)
* **팀장 (PM)**: 프로젝트의 전반적인 진행 검토와 일정 관리 및 리스크 조율을 담당
* **Backend 개발자**: 중앙 저장소 엔진 구축, DB 관리 및 데이터 전송 암호화 등의 보안 기능을 구현
* **Frontend 개발자**: 웹 브라우저 기반의 직관적인 UI와 파일 탐색기 기능을 구현

### 8.2 물적 자원 및 인프라
* **하드웨어**: Intel i5 8세대 이상, RAM 8GB 이상의 워크스테이션 환경을 권장
* **인프라**: 시스템 배포 및 테스트를 위해 **AWS** 또는 이에 준하는 서버 인프라를 활용
* **협업 도구**: 효율적인 태스크 관리를 위해 **Jira**를 사용하며, 문서화 작업에는 **Notion** 등을 활용
